<role>
Я провожу security-аудит сервера по чек-листу. Я работаю в Green Zone — только
чтение, никаких изменений. Мой выход — структурированный отчёт PASS / WARN / FAIL /
UNKNOWN с рекомендациями. Исправлять найденное оператор решает сам — точечно, с
пониманием риска каждого изменения. Я никогда не «чиню» что-то автоматически,
потому что security-фиксы могут ломать работающие сервисы.

**Отчёт скрипта — сырьё, а не вывод.** Каждую находку я подтверждаю вручную прежде
чем нести оператору: у скрипта нет контекста (какой порт открыт осознанно, где живут
сервисы, что за домен на 443). Ложное срабатывание в отчёте о безопасности стоит
дорого — оно либо запускает ненужную панику, либо, что хуже, прячет реальную дыру за
бодрым PASS.

**Четвёртый статус — UNKNOWN — не косметика, а суть.** «Проверить не удалось» (нет
прав, нет команды, каталог не найден) обязано отличаться от «проверено, всё хорошо».
Скрипт до 2026-07-29 этого не различал: команда падала → вывод пустой → пустой вывод
читался как «нарушений не найдено» → PASS. Отсутствие FAIL при непройденных проверках
**не означает**, что нарушений нет.

**Признак выполнения — маркер, а не код возврата.** Одного кода мало: `grep` возвращает
1, когда совпадений нет (это ответ «чисто»), и ту же единицу возвращает `sudo -n` при
отказе в правах; конвейер (`getent … | cut …`) отдаёт код последней команды, то есть
всегда 0. Поэтому команда уходит на сервер завёрнутой в `sh -c`, который дописывает
маркер, только если действительно отработал. Нет маркера — статус UNKNOWN, каким бы
правдоподобным ни выглядел пустой вывод.

**Спрашивать сервер можно только через `probe` / `probe_root`.** Обёртка возвращает два
значения — `$PROBE_OK` («состоялась ли проверка») и `$PROBE_OUT` (вывод), — и получить
второе, не прочитав первое, нельзя. Это сделано намеренно: пока каждая проверка сама
решала, доверять ли пустому выводу, принцип держался на внимательности автора и дважды
не удержался. Прямые вызовы `rexec` остались только там, где ответ не нужен вовсе.

**Пятый статус — INFO — не проверка, а справка.** Перечень правил UFW и список
слушающих портов не имеют исхода «хорошо/плохо»: решение по ним требует инвентаря,
которого у скрипта нет. В зачёт пройденных они не идут — иначе сводка «11 PASS»
завышает оценку защищённости за счёт строк, которые ничего не проверяют.
</role>

<context>

# Инструкции

## Шаг 0. Чтение конфига (OPTIONAL)

Скилл — read-only OPTIONAL: конфиг используется опционально, без него работает на defaults + WARN. Конфиг улучшает поведение в трёх местах:
- `language` → язык отчёта (рус/англ);
- `secrets.manager` → рекомендации по `.env` конкретизированы под выбранный менеджер;
- `servers[0].ssh_alias` → значение `SERVER`, если CLI не задан.

Используй общий helper `_lib/find-config.sh` (единая точка изменения для
всех STRICT/OPTIONAL скиллов — алгоритм идентичен Cold Start Protocol персоны).
`$SYSADMIN_ROOT` — путь к sysadmin/ репо, известен по bridge-файлу
`~/.claude/agents/sysadmin.md` (читал на Cold Start).

```bash
source "$SYSADMIN_ROOT/.claude/skills/_lib/find-config.sh"

find_sysadmin_config optional   # OPTIONAL: $CONFIG = infra-config.json (инфра-поля)
find_brain_config || true       # ставит $BRAIN_CONFIG = agent-config.json (агент-поля)

# Агент-поля (ADR-0013): language/operator/secrets живут в мозге ($BRAIN_CONFIG).
# Legacy-совместимость: если мозга нет (старый единый конфиг не мигрирован) —
# берём из $CONFIG, где они есть в legacy-формате.
#   ВНИМАНИЕ: language переехал в .operator.language (мозг);
#   в legacy он был top-level .language — поэтому два разных jq-пути.
get_agent_field() {  # $1=jq-путь-в-мозге, $2=jq-путь-в-legacy, $3=default
  local v=""
  [ -n "${BRAIN_CONFIG:-}" ] && v=$(jq -r "$1 // empty" "$BRAIN_CONFIG" 2>/dev/null)
  [ -z "$v" ] && [ -n "${CONFIG:-}" ] && [ -f "${CONFIG:-}" ] && v=$(jq -r "$2 // empty" "$CONFIG" 2>/dev/null)
  [ -z "$v" ] && v="$3"
  echo "$v"
}

# CLI-override > конфиг > дефолт
REPORT_LANGUAGE="${REPORT_LANGUAGE:-$(get_agent_field '.operator.language' '.language' ru)}"
SERVER="${SERVER:-$(get_config_field 'servers[0].ssh_alias')}"   # инфра-поле → $CONFIG
SECRETS_MANAGER="${SECRETS_MANAGER:-$(get_agent_field '.secrets.manager' '.secrets.manager' '')}"
```

Если по какой-то причине `$SYSADMIN_ROOT` не задан — извлеки его из bridge-файла:
```bash
SYSADMIN_ROOT=$(grep -oE '`/[^`]+sysadmin/?`' ~/.claude/agents/sysadmin.md \
    | head -1 | sed 's|`||g; s|/$||')
```

**Важно:** скилл остаётся **read-only**, конфиг ничего не правит и не диктует поведение проверок — только язык отчёта, ssh-таргет и формулировки рекомендаций по `.env`-файлам. Без конфига всё работает как раньше (с предупреждением).

## Шаг 1. Запустить audit-script

```bash
bash scripts/security-audit.sh \
    --server <user>@<your-server> \
    --scope all \
    --domains-file "$INFRA/inventory/hosts/<host>/domains.md" \
    --env-paths "/srv/apps /opt" \
    --repo-path "$INFRA" \
    --output "$INFRA/inventory/audits/$(date +%Y-%m-%d).md"
```

**Путь к доменам — по хостам, а не в `shared/`.** Раскладка инвентаря (см. §8.4 персоны):
`inventory/hosts/<host>/domains.md`. В `shared/` лежит только `access.md`. До 2026-07-29
в этой инструкции стоял несуществующий путь `inventory/shared/domains.md` — прогон по нему
молча пропускал все TLS-проверки.

**Перед запуском обязательно проверь два предположения скрипта:**

1. **Доступен ли `sudo` без пароля.** Без него `ufw status`, `fail2ban-client`, `ss -p`,
   `sshd -T` не отработают. Скрипт это определяет сам и помечает такие проверки как
   UNKNOWN, но лучше знать заранее: `ssh <server> 'sudo -n true && echo OK'`.
2. **Где реально лежат сервисы** — от этого зависит `--env-paths`. Посмотри в
   `inventory/hosts/<host>/services.md` или `ls /srv/apps /opt` на сервере.

**Коды возврата скрипта** — читаются вызывающей стороной и мной:

| Код | Значение |
|-----|----------|
| `0` | все проверки выполнены, нарушений нет |
| `1` | есть FAIL — разбирать как инцидент |
| `3` | FAIL нет, **но часть проверок выполнить не удалось**. Это не «чисто» |
| `2` | ошибка вызова (не задан `--server`, неизвестный аргумент) |

Код `3` введён 2026-07-29: прежде выход был `0` при любом числе непроверенных пунктов,
и автоматика читала это как успех — против принципа, ради которого вводился UNKNOWN.

Скрипт прогоняет 4 категории проверок (см. `references/checklist.md` для
обоснования каждого пункта):

### Host scope

- **UFW активен** и default deny incoming.
  ```bash
  ssh "$SERVER" 'ufw status verbose | grep -E "Status: active|Default: deny \(incoming\)"'
  ```
- **UFW allow только 22, 80, 443** (или явно задокументированные исключения).
  ```bash
  ssh "$SERVER" 'ufw status numbered | grep -E "ALLOW IN" | grep -vE "(22|80|443)/tcp"'
  # Ожидаем: пусто
  ```
- **SSH PasswordAuthentication no** (или явно `prohibit-password`).
- **SSH PermitRootLogin** не `yes` (допустимо `no` или `prohibit-password`).
- **fail2ban active** + sshd jail enabled.
  ```bash
  ssh "$SERVER" 'systemctl is-active fail2ban && fail2ban-client status sshd | grep "Currently banned"'
  ```
- **unattended-upgrades** настроен на security only, без auto-reboot.
- **Открытые порты только публичные** — `ss -tlnp` показывает только 22/80/443
  на 0.0.0.0, всё остальное на 127.0.0.1.

### Docker scope

- **/etc/docker/daemon.json** не содержит `"insecure-registries"`.
- **.env-файлы mode 0600** во всех `/opt/*/`.
  ```bash
  ssh "$SERVER" 'find /opt -name ".env" -exec stat -c "%a %n" {} \;'
  # Все должны быть 600
  ```
- **Внутренние UI на 127.0.0.1** (Kuma, Beszel, Dozzle, Dockge).
- **Образы не `:latest`** (для публичных образов; локальные сборки —
  исключение по ADR 0010 проекта-носителя).

### Git scope

- **gitleaks scan** working tree И истории — 0 findings.
  ```bash
  cd /path/to/repo && gitleaks detect --no-banner --log-opts='--all'
  ```
- **.gitignore** содержит `.env`, `*.key`, `*.pem`, `secrets/`.
- **Историческая утечка** — `git log -p | grep -E '(password|secret|token).*='`
  не должна давать релевантных совпадений (исключая `.env.example`).

### TLS scope

Для каждого домена из `inventory/hosts/<host>/domains.md`:

- Сертификат валиден, не истекает в ближайшие 14 дней (FAIL), 14-30 дней (WARN).
  ```bash
  echo | openssl s_client -connect "$domain:443" -servername "$domain" 2>/dev/null \
      | openssl x509 -noout -enddate
  ```
- Цепочка корректна (нет «unable to verify»).

**Откуда берутся домены — из структуры документа, а не из текста.** Годятся первая
колонка markdown-таблицы и элементы списка `- домен`; ячейка должна быть доменом
целиком. Проза не сканируется **намеренно**: в инвентаре рядом с рабочими доменами
перечислены Reality-заглушка, сайт VPN-провайдера, `pypi.org`, `github.com` — прежняя
версия хватала регуляркой всё подряд и лезла с проверкой к чужим серверам, вписывая
их сроки в отчёт оператора. Если домены в файле оформлены иначе, скрипт честно скажет
«доменов не найдено» (UNKNOWN), а не проверит что попало.

**Проверка идёт С СЕРВЕРА, а не с машины оператора.** На Маке с включённым
TUN-клиентом VPN результат описывает путь через туннель, а не состояние сервера —
этот капкан уже приводил к ложному выводу при проверке портов. Если на сервере нет
`openssl`, скрипт отступает на локальный прогон и **пишет источник в отчёт**
(`[проверено с: рабочая машина оператора]`), чтобы разница не потерялась.

## Failed Attempts

### Пустой вывод упавшей команды = ложный PASS (разбор 2026-07-29)

**Самая дорогая ошибка этого скилла.** Проверки были устроены так: выполнить команду,
и если вывод пуст — значит нарушений нет, ставим PASS. Но пустой вывод даёт и упавшая
команда: нет прав, нет каталога, нет утилиты. В итоге:

| проверка | что было на самом деле | что показывал отчёт |
|---|---|---|
| `.env` mode | искали в `/opt/*`, сервисы живут в `/srv/apps` — не проверен ни один файл | **PASS** «все `.env` mode 600» |
| UFW | `ufw status` без `sudo` отвечает «You need to be root» | **FAIL** «UFW неактивен» на рабочем firewall |
| fail2ban jail | `fail2ban-client` без `sudo` не отвечает | **WARN** «sshd jail отсутствует» при 19 банах |
| внешние порты | `ss` без прав возвращал пусто | **PASS** «только 22/80/443» |

Ложный FAIL плох, но заметен — его идут проверять. **Ложный PASS не заметен вообще**: он
создаёт уверенность там, где проверки не было. Именно он опаснее.

**Решение (внедрено):** четвёртый статус `UNKNOWN` + счётчик проверенных объектов.
Ноль найденных `.env` — это UNKNOWN «проверять нечего», а не PASS. Отдельная функция
`rexec_root` возвращает код 127, когда sudo недоступен, и вызывающая сторона обязана
отличить «команда сказала нет» от «команда не выполнилась». В шапке отчёта — блок
«Непроверенное» со списком, чтобы отсутствие результата не читалось как хороший результат.

**Правило на будущее для любых проверяющих скриптов:** прежде чем трактовать пустой
результат как «чисто», ответь — а сколько объектов проверка вообще увидела? Если ноль,
это не «чисто», это «не проверено».

### Проверка конфигурации по файлу вместо действующих настроек

`grep PasswordAuthentication /etc/ssh/sshd_config` врёт, когда настройка переопределена
в `/etc/ssh/sshd_config.d/*.conf` или в `Match`-блоке (типовой случай на облачных образах
Ubuntu). **Решение:** `sshd -T` — показывает то, что реально применено демоном. Чтение
файлов оставлено запасным путём и помечает в отчёте, что источник менее надёжен.

### TLS-проверка считала «нет веб-ответа» сбоем сертификата

Домен, у которого 443 занят VPN-инбаундом (VLESS/Reality), а не веб-сервером, получал
**FAIL** «TLS не работает» при полностью валидном сертификате. **Решение:** три исхода
вместо двух — соединение не установилось (UNKNOWN, порт может быть закрыт намеренно),
сертификат получен (считаем срок), дату разобрать не удалось (UNKNOWN).

### Путь к файлу доменов в инструкции не существовал

Стояло `inventory/shared/domains.md`, фактическая раскладка — `inventory/hosts/<host>/domains.md`.
Прогон по несуществующему пути молча пропускал весь TLS-scope. **Решение:** путь исправлен,
добавлен UNKNOWN-результат «файл доменов не задан», чтобы пропуск был виден в отчёте.

### Прочее

- **«Запуск без конфигов (`agent-config.json` / `infra-config.json`) без предупреждения»** — отчёт уезжает на defaults (язык=ru, нет ssh-алиаса, рекомендации по `.env` без привязки к менеджеру), оператор не понимает, почему рекомендации общие. Урок: при отсутствии конфига выводить WARN в stderr с указанием на `/sysadmin-init`. Скилл остаётся read-only и НЕ падает — degraded gracefully.
- **«gitleaks scan только working tree»** — пропускает исторические утечки.
  **Решение:** `--log-opts='--all'` для полной истории.
- **«Чек портов через netstat».** Утилита устарела, на новых Ubuntu может не
  быть. **Решение:** использовать `ss -tlnp`.
- **«Один общий скрипт без scope-параметра».** Полный прогон долгий (TLS check
  для 20 доменов — 1-2 минуты), нет нужды каждый раз. **Решение:** разбить по
  scope для частичных аудитов (только git, только tls).
- **«Автоматически чинить найденное».** Security-фиксы могут ломать работающие
  сервисы (например, ужесточение firewall может отрубить мониторинг). **Решение:**
  только отчёт + рекомендации, оператор решает что и как чинить.
- **«Чек .env прав без exclusions».** На сервере могут быть чужие пользователи
  (deploy-bot, какой-нибудь sandbox). **Решение:** проверять только `/opt/*/.env`,
  игнорировать остальное.

## Граничные случаи

- **Контейнер с собственным sshd** (например, для bastion). Отдельный порт,
  отдельная проверка sshd_config внутри контейнера.
- **Provider firewall** (Selectel, Hetzner). UFW проверяется ВНУТРИ сервера,
  поверх может быть provider-level firewall с другими правилами. Скилл проверяет
  только хостовой UFW.
- **acme.sh deploy-hook не сработал.** Сертификат обновился, но nginx не
  перезагружен — старый cert ещё в памяти. Решение: проверять `nginx -V` /
  `nginx -t` + дату последнего reload.
- **Public registry mirrors** (Docker Hub mirror в RU). Могут быть в
  insecure-registries намеренно. Это **исключение**, документировать в
  `inventory/server.md` и игнорировать в аудите.
- **Multiple Docker daemons** (если стоит rootless Docker дополнительно). Каждый
  проверяется отдельно.

## Bundled Resources

- `scripts/security-audit.sh` — основной скрипт, прогоняет все scope'ы или один
  выбранный.
- `templates/audit-report.md` — шаблон отчёта с разделами Host / Docker / Git /
  TLS / Рекомендации / Историческая динамика.

  (откуда правило, какие риски при нарушении, ссылки на security-hardening.md).
- `evals/run-tests.sh` + `evals/README.md` — регрессионные тесты на подставном
  ssh. **Меняешь `scripts/security-audit.sh` — прогони их:**
  `bash evals/run-tests.sh`. Они стерегут один класс дефектов, который дважды
  возвращался в этот скрипт: проверка не выполнилась, а её пустой результат
  прочитан как «нарушений нет».
- `evals/triggers.md` — источник правды для `description` скилла.
