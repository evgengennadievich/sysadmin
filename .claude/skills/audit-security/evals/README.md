# Регрессионные тесты `/audit-security`

```bash
bash .claude/skills/audit-security/evals/run-tests.sh
```

Выход `0` — всё прошло, `1` — есть провалившиеся. Для разбора провала:
`KEEP=1 bash evals/run-tests.sh` (временная папка с отчётами и логами не удаляется).

## Зачем они есть

У этого скрипта один повторяющийся класс дефектов: **проверка не выполнилась, но её
пустой результат прочитан как ответ**. Наружу это выходит как `PASS` там, где не
проверялось ничего, — спокойствие без основания.

Дефект возвращался дважды:

| когда | что было |
|---|---|
| до 2026-07-29 | права `.env` искались в `/opt`, сервисы жили в `/srv/apps` → «PASS, все `.env` mode 600» при нуле проверенных файлов |
| правка 066fc80 | вводила статус UNKNOWN — и **сама принесла новый ложный PASS**: конвейер `getent \| cut` возвращал код `cut` (всегда 0), поэтому отсутствие утилиты читалось как «группа docker пуста» |

Чтением кода это не ловится: оба раза логика выглядела правильной. Дефект живёт в
связке «локальная логика + поведение удалённой команды», поэтому тесты подменяют
**сам транспорт**.

## Как устроено

- `stub-bin/ssh` — подставной ssh. Отбрасывает опции, обрабатывает префикс `sudo -n`
  (при `STUB_SUDO=deny` отказывает ровно как настоящий sudo: код 1 и сообщение в
  stderr — именно неотличимость этой единицы от grep-«ничего не найдено» и была
  корнем дефектов), подменяет системные пути фикстурами и выполняет команду локально.
- `stub-bin/{ufw,systemctl,getent,ss,sshd,fail2ban-client}` — заглушки серверных
  утилит. Поведение задаётся переменными `STUB_UFW`, `STUB_SYSTEMCTL`, `STUB_GETENT`,
  `STUB_SSHD`. Значение `missing` — «утилиты нет в системе» (код 127).
- `stub-bin/stat` — эмулирует GNU-формат `stat -c` поверх BSD stat, чтобы проверку
  прав `.env` можно было гонять на Маке, а не только на Linux-сервере.
- Фикстуры (`sudoers`, деревья с `.env`) создаются во временной папке **на прогоне**.
  В репозиторий они не кладутся сознательно: файлы с именем `.env` в дереве
  инструмента, который сам ищет утечки секретов, — плохая идея.

## Что именно стерегут

| # | Сценарий | Ожидание | Какой дефект стережёт |
|---|---|---|---|
| 1 | sudo есть, правил NOPASSWD нет | `PASS` | ветка PASS была **недостижима**: `grep` без совпадений отдаёт код 1, и это считалось сбоем |
| 1 | перечень правил UFW, список портов | `INFO` | справки не должны идти в зачёт пройденных проверок |
| 2 | sudo недоступен | `UNKNOWN` + код 3 | без root результата нет; выход `0` читался как успех |
| 3 | `getent` отсутствует | `UNKNOWN` | ложный `PASS` «группа docker пуста» |
| 4 | группы docker нет | `PASS` | код 2 у `getent` — штатный ответ, а не сбой |
| 5 | `systemctl` отсутствует | `UNKNOWN` | пустой ответ давал `FAIL` «не запущен» |
| 6 | fail2ban выключен | `FAIL` + код 1 | настоящее нарушение обязано остаться нарушением |
| 7 | `.env` с правами 644 | `WARN` | нарушение находится |
| 7 | `.env` все 600, поиск под root | `PASS` | законный PASS не должен теряться |
| 7 | `.env` все 600, но без root | `UNKNOWN` | `find` без прав молча пропускает каталоги — «все 600» утверждать нельзя |
| 8 | пути пусты | `UNKNOWN`, без слов «все mode 600» | исходный дефект 2026-07-29 |
| 9 | `domains.md` с прозой | домены из таблицы есть, `github.com` и прочие чужие — нет | регулярка по всему тексту тащила в проверку чужие домены: мусор в отчёте и соединения с третьими лицами от имени оператора |
| 10 | `sshd -T` недоступен | `UNKNOWN` по интерактивной аутентификации | проверка молча пропадала из отчёта — отсутствовала бесшумно |
| 11 | `--scope hosts`, `--help` | коды 2 и 0 | опечатка в scope давала пустой отчёт с кодом «успех» |

## Правило

**Меняешь `scripts/security-audit.sh` — прогони эти тесты.** Добавляешь новую
проверку — добавь сценарий, где её команда недоступна, и убедись, что статус
`UNKNOWN`, а не `PASS`. Стенд поймал ошибку в самом себе при первом же прогоне
(подстановка путей через `${var//…}` со слэшем в начале шаблона) — он работает.
