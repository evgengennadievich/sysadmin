# Канон текстов канала «сисадмин ↔ разработчик»

Источник: тексты, развёрнутые в FKS, BotDesigner и T-plus (август 2026). Порядок выкаток
утверждён оператором 20.08.2026 — менять его формулировку без решения оператора нельзя.
Подстановки: `{ПРОЕКТ}`, `{КАТАЛОГ}` (путь на сервере), `{ОСОБЕННОСТИ}` (из разведки),
`{ДАТА}`, `{СОСТОЯНИЕ}` (синхронизация боевого клона).

## Файл 1: `INFRA-CHANGELOG.md`

```markdown
# Журнал инфраструктурных изменений ({ПРОЕКТ})

Что это. Изменения на **боевом сервере** (`madik`, каталог `{КАТАЛОГ}`) со стороны
эксплуатации: лимиты, расписания, секреты, службы. Ведёт агент-сисадмин оператора;
код приложения он не трогает. Новая запись — сверху; у каждой обязательны **причина**
(с цифрами замера) и **способ отката**.

## Связь сисадмин ↔ разработчик (порядок утверждён Евгением 20.08.2026)

Обе стороны меняют одну систему, поэтому канал один — этот репозиторий и его GitHub.
Устные договорённости и правки «руками на сервере» вне git запрещены обеим сторонам.

**Разработчик:**
1. Готовую работу публикует **только на GitHub**, и только после согласования с
   Евгением. На боевой сервер не выкатывает: ни pull, ни build, ни рестартов.
2. Сразу после публикации — **обязательная запись в `docs/SYSADMIN-HANDOFF.md`**:
   что едет, какие файлы инфраслоя тронуты, что требуется при выкатке.
   Выкатка без записи не выполняется.
3. Задания от сисадмина читает там же и отвечает в разделе задания.
4. Встречные вопросы — GitHub issue с префиксом `[инфра]`, не чаты.

**Сисадмин:**
1. Проверяет запись и код (секреты, опасные конструкции, внешние адреса), затем
   выкатывает на сервер с «ок» Евгения на окно.
2. Свои изменения на боевом записывает сюда коммитом, с причиной и откатом.

{ОСОБЕННОСТИ}

---

## {ДАТА} — журнал заведён

{СОСТОЯНИЕ}
```

## Файл 2: `docs/SYSADMIN-HANDOFF.md`

```markdown
# Служебный канал {ПРОЕКТ}: задания и ответы

Что это. Двусторонний канал сисадмин ↔ разработчик. Сисадмин пишет здесь **задания и
инструкции**; разработчик **отвечает в разделе задания**, что сделал, и публикует
работу на GitHub; после этого сисадмин выкатывает на сервер. Схема общая для всех
проектов Евгения. Протокол целиком — [INFRA-CHANGELOG.md](../INFRA-CHANGELOG.md).

Правила: новое задание — разделом сверху; чужие разделы не правятся, только
дописывание своего ответа; статусы меняются коммитом.
Статусы: `ожидает ответа` | `в работе` | `готово к выкатке` | `выкачено (дата)` |
`отклонено (причина)`.

---
```

## Раздел «особенности» — что туда попадает (из разведки, не из головы)

Связки, которые нельзя рвать молча: чужие токены и общие секреты (пример T-plus:
алерты через токен infra-бота — ротация ломает проект); живые bind-mount конфиги
(пример FKS: каталог config примонтирован в контейнер — правки действуют без выкатки);
самообновление через git (пример T-plus); тяжёлые шаги сборки (пример BotDesigner:
next build однажды подвесил сервер); расписания cron и кто их правит.
