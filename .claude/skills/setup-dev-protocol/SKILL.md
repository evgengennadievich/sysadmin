<role>
Я разворачиваю в репозитории проекта стандартный канал связи с разработчиком — тот же,
что уже работает в FKS, BotDesigner и T-plus. Работаю с GitHub-репозиторием оператора;
на боевой сервер выхожу только читать факты об устройстве проекта.
</role>

# Параметры

| Параметр | Как получить |
|---|---|
| `REPO` | имя GitHub-репозитория; не назван — спросить оператора одним вопросом |
| Факты о проекте | живой разведкой (см. Шаг 2), не из головы |

# Процедура

## Шаг 1. Клон и идемпотентность

Склонировать репозиторий неглубоко в scratchpad. Если `INFRA-CHANGELOG.md` **уже есть** —
канал развёрнут: не перезаписывать, а сверить протокол с каноном
(`references/protocol-template.md`), доложить оператору расхождения и остановиться.

## Шаг 2. Разведка фактов (Green)

Перед шаблоном — факты, без них раздел «особенности проекта» будет выдумкой (C.2):

- где проект живёт на сервере (`/srv/apps/...`?), как запускается (compose / systemd /
  cron / самообновление через git);
- как выкатывается (пересборка? `git pull`? живые bind-mount конфиги?);
- связки, которые нельзя рвать молча: чужие токены, туннель, расписания, общие секреты;
- синхронен ли боевой клон с GitHub прямо сейчас (это ответ на «что выкатывать»).

Проект на сервере не найден — канал всё равно разворачивается, в «особенностях» честно
пишется «на боевом сервере не развёрнут (дата)».

## Шаг 3. Два файла из шаблона

Тексты — из `references/protocol-template.md`, дословно, с подстановкой фактов Шага 2:

1. `INFRA-CHANGELOG.md` — журнал + протокол (порядок оператора от 20.08.2026 менять
   нельзя без его решения) + раздел «особенности проекта» по фактам + первая запись
   «журнал заведён» с состоянием синхронизации.
2. `docs/SYSADMIN-HANDOFF.md` — служебный файл: правила, статусы, **Задание 001
   «что готовится к выкатке?»** с тремя вопросами разработчику (что публикуешь;
   что потребуется от сервера; устраивает ли текущий запуск).

## Шаг 4. Проверка и отправка

`gitleaks protect --staged` перед коммитом; коммит на русском
(`docs(infra): канал связи с сисадмином — журнал и служебный файл заданий`); push.

## Шаг 5. Замыкание

- дополнить память агента (заметка о схеме следов в чужих проектах): проект подключён;
- сказать оператору фразу для разработчика: «прочитай docs/SYSADMIN-HANDOFF.md и ответь
  на задание 001»;
- доложить состояние синхронизации боевого клона (и есть ли что выкатывать уже сейчас).

# Границы

- Файлы в чужом репозитории — только эти два, чужие разделы и код не трогать (ADR-0034).
- Выкатки по ответам разработчика — отдельная работа сисадмина со своими зонами,
  не часть этого скилла.
