# Мониторинг-стек: грабли и граничные случаи

Справка к скиллу `/install-monitoring-stack`. Открывать, когда шаг не сработал так, как
написано в процедуре, или когда сервер не похож на типовой (нет публичного IP, стоит CDN,
серверов несколько).

Выбор состава стека и RAM-бюджет — другой документ, `component-tradeoffs.md`.

---

## Грабли, на которых уже спотыкались

**Запуск без конфига инфры (`infra-config.json`).** Раньше скилл требовал десяток
CLI-параметров, и оператор путался, какие обязательные. Урок: скилл не угадывает
намерения. Нет конфига — `exit 1` с указанием на `/sysadmin-init`.
`monitoring.enabled=false` — `exit 0` с указанием на `/sysadmin-init --reconfigure`.
Никаких значений по умолчанию «как у знакомого оператора».

**Python-библиотека `uptime-kuma-api` для Kuma 2.x** — НЕ работает, она только для 1.x:
в 2.x изменился socket.io-протокол. Единственный путь — Node.js socket.io клиент.

**Beszel hub в bridge-сети** — iptables блокирует порт agent'а (45876) со стороны Docker
bridge gateway, agent недостижим. Только `network_mode: host`. Изоляцию в этом случае
даёт не сеть Docker, а `ufw deny 8090/tcp`.

**Теги `:latest`** — Docker Compose сравнивает строку image, а не digest. При `:latest` он
пересоздаёт контейнер на каждый `up -d`, даже если digest не менялся. Версии в шаблонах
всегда запинены конкретными номерами (или digest).

**`acme.sh` без `--reloadcmd`** — после обновления сертификата nginx продолжает отдавать
старый, пока кто-нибудь вручную не сделает reload. `--reloadcmd "nginx -s reload"`
указывать всегда.

**`htpasswd` с `-i`** — пароль попадает в историю shell. Использовать `htpasswd -c -B`
без `-i`, с интерактивным вводом.

## Граничные случаи

Четыре главных разобраны в `component-tradeoffs.md`, раздел «Особые случаи»: сервер за
CDN, сервер без публичного IP (варианты вместо HTTP-01), несколько серверов на один hub,
сервер с памятью меньше 1 ГБ. Сюда их не дублирую — там они с вариантами решения.

Пятый, которого там нет:

**WireGuard или приватная сеть.** Сервер недоступен из публичного интернета — vhost
открывается только на VPN-интерфейсе (`listen 10.0.0.1:443`), без Let's Encrypt:
internal CA или mkcert. Установка только Kuma при этом даёт nginx-конфигурацию с одним
upstream и бюджет памяти ~50 МБ вместо ~250.

## Что писать в inventory после установки (Шаг 10)

Строки в `inventory/services.md` — по одной на контейнер, формат таблицы этого файла.
Образец (версии подставить фактические, из своих compose-файлов, а не отсюда):

```
uptime-kuma  | мониторинг | 127.0.0.1:3001 | panel.$DOMAIN/         | louislam/uptime-kuma:<версия>
beszel       | мониторинг | host:8090      | panel.$DOMAIN/beszel/  | henrygd/beszel:<версия>
beszel-agent | мониторинг | host:45876     | (внутренний)           | henrygd/beszel-agent:<версия>
dozzle       | логи       | 127.0.0.1:8080 | panel.$DOMAIN/dozzle/  | amir20/dozzle:<версия>
dockge       | compose UI | 127.0.0.1:5001 | panel.$DOMAIN/dockge/  | louislam/dockge:<версия>
diun         | image upd  | (нет порта)    | (через Telegram)       | crazymax/diun:<версия>
```

Версии берутся из шаблонов `templates/*.yml` на момент установки — переписывать их сюда
руками нельзя, иначе документ начнёт врать при первом же обновлении образа (C.2).
