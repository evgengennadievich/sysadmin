# Серверный прокси: грабли и граничные случаи

Справка к скиллу `/setup-server-proxy`. Открывать, когда шаг не сработал так, как написано
в процедуре, или когда сервер не похож на типовой.

Две узкие темы разобраны отдельно: почему буква `h` в `socks5h` критична —
`socks5-vs-socks5h.md`; библиотеки, которые не уважают `HTTPS_PROXY`, —
`python-libs-with-proxy.md`.

---

## Грабли, на которых уже спотыкались

**🔴 Запись `/etc/environment` без systemd-override → панель упала с `INVALIDARGUMENT`.**
Главная грабля всего VPN-блока. x-ui подхватывает `HTTPS_PROXY` из окружения и начинает
ходить сам через свой же mixed inbound — получается петля, панель падает. Поэтому override
делается **первым шагом**, а `03-write-environment.sh` отдельно проверяет его наличие перед
записью. Это рефлекс §3.8.2 персоны, а не рекомендация.

**`socks5://` без `h`.** Anthropic API отвечает 403: DNS резолвится локально, геолокация
выдаёт исходную страну. Скилл всегда пишет `socks5h`. Разбор — `socks5-vs-socks5h.md`.

**Mixed inbound на `0.0.0.0`.** Без авторизации прокси торчит в интернет и может
использоваться кем угодно. Скилл требует явного подтверждения, если оператор настаивает
на адресе, отличном от `127.0.0.1`.

**Sniffing на mixed-inbound выключен.** Прокси видит только IP назначения, и domain-правила
(реклама `category-ads-all`, сервисы на `.com`) для серверных программ мертвы — остаётся
грубое деление по geoip. На боевом сервере он был ВЫКЛ. `02-create-mixed-inbound.sh` всегда
создаёт inbound со sniffing `{enabled:true, destOverride:["http","tls","quic"]}`.

**Упрощённая модель `geoip:ru → direct, остальное → upstream`.** Старый вариант (до мая
2026): реклама не резалась, regex по национальным доменам отсутствовал. Заменён
шестиправильной моделью «золотая середина», scoped на mixed-inbound.

**`regexp:.*\\\\.ru$` — четыре бэкслеша в jq-источнике.** Давало рантайм-regex `\\.`
(литеральный бэкслеш), домены не матчились. Правильно — два бэкслеша в jq-источнике:
`regexp:.+\\.ru$`.

**Текущая SSH-сессия не подхватила переменные.** Это не сбой: окружение читается при
логине. Оператору нужен новый `ssh` или `source /etc/environment` в текущей сессии.

## Граничные случаи

**На сервере уже есть свой mixed inbound на другом порту** — скилл идемпотентен:
использует существующий с указанным портом либо создаёт новый на свободном.

**Upstream-outbound прописан только в правилах для VLESS-inbound, не для mixed** — скилл
явно добавляет правило `inboundTag=mixed-server-proxy → upstream` и не зависит от того,
что уже настроено для клиентских инбаундов.

**Балансировщика нет, outbound один** — автоопределение: вместо `balancerTag` используется
`outboundTag`.

**Программа живёт в Docker-контейнере** — переменные из `/etc/environment` в контейнер
сами НЕ попадают. Нужен явный проброс в compose (`environment: - HTTPS_PROXY`). Скилл
предупреждает об этом в финальном отчёте.

## Что через этот прокси не пойдёт вообще

Известные исключения — для них нужен HTTP-прокси (Privoxy поверх SOCKS), это отдельная
задача:

- **apt** — не поддерживает SOCKS5;
- **Node.js core `http`/`https`** — не уважает `HTTPS_PROXY` нативно;
- **Go stdlib** — понимает только HTTP/HTTPS-прокси; для SOCKS нужен
  `golang.org/x/net/proxy`.
