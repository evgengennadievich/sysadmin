# ADR-0024: Снимок сервера собирается и без Docker (fail-soft вместо fail-fast)

**Статус:** принят (2026-07-24)

## Контекст

`dump-snapshot.sh` начинался с жёсткой проверки: нет Docker на хосте → сообщение «Docker не
установлен — снимок контейнеров невозможен» → `exit 1`. Наличие Docker было **условием
запуска**, а не свойством хоста.

Кейс с боевой инфры ученика (Алексей, поток «Архитектор ИИ-решений», 2026-07-24): нативный
VPS с 3X-UI и nginx, **Docker не установлен вовсе** — сервисы работают как systemd-юниты.
`/inventory-scan` не смог отработать в принципе. Агент повёл себя правильно — не стал гнать
заведомо падающий скрипт и не выдумал снимок (C.9), — но синхронизировать inventory
автоматически не смог: пришлось руками сверять сервер и править четыре документа.

Класс проблемы шире одного ученика: нативные VPS без Docker — обычное дело (VPN-сервер,
одиночный сервис, лёгкая коробка). Для них `/inventory-scan` был **недоступен как класс**.
А это тот самый инструмент, который держит текстовое зеркало в соответствии с реальностью:
нет автосинхронизации → зеркало устаревает → агент доверяет старым заметкам вместо фактов.
То есть баг **подпитывал** ровно ту болезнь, которую лечат ADR-0021 и ADR-0023.

## Решение

**1. Docker — определяемое свойство хоста, а не предусловие.** Скрипт больше не падает.
`meta.txt` объявляет тип хоста, и это **три** состояния, а не два (третье вскрылось живым
прогоном — CLI установлен, а демон не отвечает):

| `host_kind` | Условие | Секции контейнеров | Смысл |
|---|---|---|---|
| `docker` | `docker info` отвечает | собраны | как раньше |
| `native` | CLI отсутствует | `NOT_APPLICABLE` | контейнеров нет — **факт** |
| `docker-down` | CLI есть, демон молчит | `NOT_APPLICABLE` | состояние **неизвестно** |

Разница двух последних принципиальна: «контейнеров нет» и «я не смог посмотреть» — разные
утверждения (C.2). `docker-down` на боевом хосте — повод сказать оператору, что служба лежит.

**2. Пропущенные секции создаются как файлы с маркером** `NOT_APPLICABLE: <причина>` в первой
строке, а `containers-inspect.json` — валидный пустой массив. Молчаливое отсутствие файла
verify скилла расценил бы как битый снимок, и агент решил бы, что сбор провалился.

**3. Verify стал зависеть от типа хоста.** Общие ключевые файлы для любого хоста —
`host-resources`, `host-services`, `firewall`; контейнерные проверяются только при
`host_kind=docker`.

**4. Добавлена секция `firewall.txt`** — UFW, iptables, nftables. На нативном хосте картина
«что открыто наружу» складывается из `ss` + firewall, без Docker-портов. Docker-хостам она
полезна не меньше: `docker publish` обходит UFW, и расхождение видно только при обоих срезах.

**5. `health-flags`:** контейнерные метрики на хосте без Docker пишутся как `n/a` с причиной,
а не как `0` (ноль означал бы «контейнеров нет проблемных», что неправда). Добавлен
`failed_units` — для нативного хоста это главный индикатор здоровья.

**6. Регрессионный тест** `tests/test-native-host.sh` (21 проверка): имитирует хост без Docker
урезанным `PATH`, проверяет успешное завершение, полноту набора файлов, маркеры и то, что
нативные источники состояния собраны. Офлайновый, сервер не трогает.

## Последствия

- (+) Владелец нативного VPS получает такой же полноценный `inventory` с drift-report, как
  владелец Docker-хоста. `/inventory-scan` перестаёт быть скиллом «только для Docker».
- (+) Закрыт канал подпитки главной болезни: зеркало таких хостов больше не протухает молча.
- (+) `firewall.txt` усиливает снимок всех хостов, не только нативных.
- (+) Различие `native` / `docker-down` не даёт выдать слепую зону за факт.
- (−) Снимок нативного хоста беднее по составу: часть файлов — заглушки. Это честное
  отражение реальности, но при сравнении снимков разных хостов надо смотреть `host_kind`.
- (−) `docker info` добавляет один вызов по SSH при сборе (доли секунды).
- Ограничение: типы хостов определяются только по Docker. Podman, LXC, k8s скрипт не знает —
  такие хосты выглядят как `native`. Появится спрос — отдельное решение.

## Связанное

- ADR-0019 — один источник фактов (снимок), ADR-0009 — отделение stderr в снимке.
- ADR-0021 / ADR-0023 — борьба с расхождением карты и реальности; этот баг ей мешал.
- Конституция C.2 (не выдумывать: «нет» и «не видел» — разные ответы), C.9 (честный STOP
  вместо суррогата — так агент и поступил в исходном кейсе).
- Скилл `/inventory-scan`: `SKILL.md`, `scripts/dump-snapshot.sh`, `tests/test-native-host.sh`.
