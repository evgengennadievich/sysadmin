# 0042: Codex как вторая среда исполнения, без отказа от Claude Code

**Статус:** Принято
**Дата:** 2026-11-18
**Автор:** Оператор (решение), агент (реализация)

## Контекст

- Оператор переходит с Claude Code на Codex (CLI 0.169, расширение VS Code). Условие
  оператора: файлы Claude не удалять, а переписать для Codex.
- Мозг был привязан к Claude Code шестью механизмами: ядро `CLAUDE.md`, скиллы в
  `.claude/skills/`, хуки в `.claude/settings.json`, автопамять `~/.claude/projects/.../memory/`,
  мост `~/.claude/agents/sysadmin.md`, headless-прогон `claude -p` и разбор записи
  `~/.claude/projects/*.jsonl` (замки, `/retro`, замер токенов).
- Codex читает `AGENTS.md` (до `project_doc_max_bytes`, по умолчанию 32 КиБ вместе с
  глобальным `~/.codex/AGENTS.md`), скиллы ищет в `.agents/skills/`, хуки в
  `.codex/hooks.json` (только у доверенного проекта и после одобрения в `/hooks`),
  пользовательских субагентов в `~/.codex/agents/*.toml`.
- **Найдена дыра, которую нельзя было перенести как есть.** В записи Codex текст AGENTS.md
  лежит строкой с `role: "user"`, а в ядре есть образец фразы красной зоны. Замок, читающий
  «все реплики user» по правилу Claude, открылся бы сам, без оператора.
- Рассмотренные варианты: (а) полный переезд с удалением `.claude/` и переписыванием ~60
  путей; (б) только документ-план; (в) двойная поддержка с одним источником истины.

## Решение

Мы держим один мозг для двух сред (вариант в):

1. **Ядро одно.** `AGENTS.md` не пишется руками: `scripts/build-agents-md.sh` собирает его
   из `codex/AGENTS.header.md` (адаптер: чем Codex отличается) и `CLAUDE.md`. Совпадение
   проверяет pre-commit (секция 1а). Предел Codex поднят: `project_doc_max_bytes = 98304`
   в `.codex/config.toml` и `~/.codex/config.toml`.
2. **Скиллы одни.** `.agents/skills/<имя>` содержат относительные ссылки на `.claude/skills/<имя>`.
   Для девяти скиллов с `disable-model-invocation` (ADR-0027) рядом лежит
   `agents/openai.yaml` с `allow_implicit_invocation: false`. В Codex для вызова используется `$имя`.
3. **Замки одни.** `.codex/hooks.json` вызывает те же скрипты `.claude/hooks/*`. Формат записи
   Codex разбирает один модуль `codex_transcript.py`; голос оператора там **только**
   `event_msg/user_message`, сессия субагента реплик оператора не имеет. Поведение под
   Claude Code не меняется (все прежние тесты зелёные), новый тест `test-codex-hooks.sh`
   ловит подмену фильтра.
4. **Память хранится в файле в приватной инфре.** Автопамять Claude скопирована в
   `$INFRA/автопамять/` (оригинал не тронут); Cold Start, Шаг 3, п. 4 читает её индекс.
   Встроенная память Codex источником истины не считается.
5. **Мост и инструменты.** `write-bridge.sh` пишет и `~/.codex/agents/sysadmin.toml`;
   `find-config.sh` находит корень по нему. `/retro`, `token-usage.sh` и `run-evals.sh`
   (`EVAL_ENGINE=codex`) понимают Codex.

## Последствия

- ✅ Мозг работает в обеих средах, откат на Claude Code ничего не требует.
- ✅ Слияния с upstream (`vefmvai/sysadmin`) не ломаются: пути `.claude/` прежние.
- ✅ Дыра «фраза из AGENTS.md открывает замок» закрыта до того, как стала инцидентом.
- ⚠️ Хуки Codex проверяют поддерживаемые вызовы инструментов. Часть путей
  инструментов проходит вне проверки хуками. Процедура §6.3 обязательна и без замка.
- ⚠️ Хуки Codex не работают, пока оператор не одобрит их в `/hooks`; адаптер требует
  от агента сказать об этом первой строкой.
- ⚠️ Подстановки ``!`…` `` в скиллах Codex не выполняет: агент запускает их вручную
  (правило в адаптере). `allowed-tools` Codex не применяет.
- ⚠️ Две копии оперативной памяти, пока оператор пользуется обоими агентами; сверка
  описана в `$INFRA/автопамять/README.md`.
- ⚠️ Формат записи Codex официально нестабилен: TTL знания 60 дней, при обновлении Codex
  прогонять `test-codex-hooks.sh` (последний блок читает настоящую запись).
