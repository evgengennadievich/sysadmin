# 05 — Документация Claude Code: устройство скиллов

**Источник:** https://code.claude.com/docs/en/skills (живой документ, читан 2026-07-25)

## Когда заводить скилл

> «Create a skill when you keep pasting the same instructions, checklist, or multi-step
> procedure into chat, **or when a section of CLAUDE.md has grown into a procedure rather
> than a fact**.»

Вторая половина — прямой критерий разгрузки ядра: **раздел ядра, который превратился
из факта в процедуру, обязан переехать в скилл.**

> «Unlike CLAUDE.md content, a skill's body loads only when it's used, so long reference
> material costs almost nothing until you need it.»

## Жёсткие ограничения, о которых надо знать

| Что | Ограничение |
|---|---|
| `description` + `when_to_use` в списке скиллов | **обрезается на 1536 символах** — ключевой сценарий ставить первым |
| Тело `SKILL.md` | ориентир **до 500 строк**, детали — в отдельные файлы рядом |
| Тело после загрузки | **остаётся в контексте на все последующие ходы** — каждая строка стоит повторно |

Про последнее прямая цитата:

> «Keep the body itself concise. Once a skill loads, its content stays in context across
> turns, so every line is a recurring token cost. State what to do rather than narrating
> how or why.»

**«Что делать» вместо «как и почему».** Объяснения — в файлы рядом, не в тело.

## Устройство папки скилла

```
my-skill/
├── SKILL.md        # точка входа: обзор и навигация (обязателен)
├── reference.md    # подробности — грузится по требованию
├── examples.md     # примеры — грузятся по требованию
└── scripts/
    └── helper.py   # исполняется, а не читается в контекст
```

Вспомогательные файлы надо **упоминать в SKILL.md**, чтобы модель знала, что там лежит
и когда туда идти. Иначе они мертвы.

> Наши скиллы этот приём почти не используют: у большинства всё в одном `SKILL.md`,
> самые крупные — 507 и 493 строки.

## Поля frontmatter, полезные нам

| Поле | Что даёт |
|---|---|
| `description` | по нему модель решает, звать ли скилл. Главное поле |
| `when_to_use` | дополнительные триггерные фразы; считается в тот же лимит 1536 символов |
| `disable-model-invocation: true` | **только оператор может позвать**. Для процедур с побочными эффектами — деплой, отправка, ротация. «Не хочешь, чтобы Claude решил задеплоить, потому что код выглядит готовым» |
| `user-invocable: false` | **только модель может позвать**. Для фоновых знаний, которые не действие |
| `allowed-tools` | инструменты без запроса разрешения на время хода |
| `disallowed-tools` | инструменты, убранные из набора на время работы скилла |
| `paths` | скилл подхватывается автоматически **только при работе с файлами по маске** |
| `context: fork` | запуск в отдельном контексте субагента |
| `model`, `effort` | модель и уровень усилий на время работы скилла |
| `hooks` | хуки, привязанные к жизненному циклу самого скилла |

`disable-model-invocation: true` имеет ещё один эффект: **описание такого скилла не висит
в контексте постоянно**, оно грузится только при вызове. То есть это ещё и способ экономии.

## Встроенные скиллы, относящиеся к теме

- `/doctor` — проверка настройки; с версии 2.1.206 предлагает урезать закоммиченный
  CLAUDE.md и диагностирует, почему скилл не срабатывает (в том числе переполнение
  бюджета описаний, из-за которого ключевые слова молча отбрасываются).
- `/verify` — собрать и запустить приложение, чтобы подтвердить, что правка делает
  обещанное, **не подменяя это тестами и проверкой типов**.
- `/run`, `/run-skill-generator` — запуск приложения и запись рецепта запуска в
  проектный скилл.
- `/code-review` — ревью текущего изменения свежим субагентом.

С версии 2.1.215 `/verify` и `/code-review` запускаются **только по команде оператора** —
раньше модель могла звать их сама. Причина: это долгие и дорогие проверки, момент их
запуска оставили человеку.

## Динамический контекст

В теле скилла строка вида `` !`git diff HEAD` `` выполняется **до** того, как модель увидит
скилл, и подменяется выводом команды. То есть скилл может приходить уже с подставленным
фактическим состоянием, а не с инструкцией «сначала посмотри».

> Приём, который нам прямо подходит: скилл диагностики может приносить снимок состояния
> сразу, а не тратить ход на его сбор.
