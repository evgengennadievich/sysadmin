# 01 — The new rules of context engineering for Claude 5 generation models

**Автор:** Thariq Shihipar (Anthropic, команда Claude Code)

## Главный факт

Из системного промпта Claude Code для новых моделей (Opus 5, Fable 5) убрали **больше 80%
текста**. Замеры качества не просели. Вывод авторов: значительная часть длинных промптов
была подпорками под ограничения прежних моделей, а для новых она стала шумом.

## Шесть сдвигов «было → стало»

### 1. Правила → суждение

Было: `Default to writing no comments. Never write multi-paragraph docstrings.`
Стало: `Write code that reads like the surrounding code: match its comment density, naming, and idiom.`

Жёсткое правило заменяется описанием **цели и критерия**. Модель сама выбирает поведение
под ситуацию. Прежние конструкции «никогда не X» ломались на исключениях, которых автор
не предусмотрел.

### 2. Примеры использования инструментов → проектирование интерфейса

Примеры в промпте («вот как вызывать этот tool») **сужают** пространство поиска у сильной
модели: она начинает копировать образец вместо того, чтобы придумать лучшее. Вместо примеров —
хорошие имена параметров, выразительные типы, внятное `description` у инструмента.

### 3. Всё заранее → прогрессивная выдача (progressive disclosure)

Детальные процедуры (у Anthropic — верификация и код-ревью) вынесены из системного промпта
в **скиллы**, которые подгружаются, когда понадобились. Постоянная стоимость контекста
падает, доступность знания не страдает.

### 4. Повторение → лаконичность

Одно и то же правило, продублированное в системном промпте и в описании инструмента, —
чистые потери. Оставлять надо **одно место**, и лучше это описание инструмента (оно ближе
к точке применения).

### 5. Ручная память → автопамять

Раньше знание между сессиями надо было руками писать в CLAUDE.md. Теперь модель сама
сохраняет то, что сочла полезным на будущее (механика — в [конспекте 04](04-docs-best-practices.md)).

### 6. Простые спеки → богатые ссылки

Модель лучше работает не с описанием задачи прозой, а с **материалом**: рабочий код,
HTML-макет, набор тестов, подробная рубрика оценки. «Покажи», а не «расскажи».

## Рекомендуемая раскладка контекста

| Слой | Что туда | Заметка |
|---|---|---|
| **Системный промпт** | контекст продукта, базовое поведение | пользователь обычно не правит |
| **CLAUDE.md** | лёгкое описание репозитория + грабли, специфичные именно для него | не пересказывать то, что видно из кода |
| **Скиллы** | мнения и практики команды, процедуры | грузятся по надобности |
| **References** | богатый материал: код, спеки, макеты | подтягиваются через `@`-ссылки |

## Инструмент

Упомянута команда `/doctor` в Claude Code — «ужимает» скиллы и CLAUDE.md под новые модели.
Документация подтверждает: начиная с версии 2.1.206 `/doctor` предлагает урезать
закоммиченный CLAUDE.md — вырезает то, что модель выведет из кода сама (раскладка каталогов,
списки зависимостей, обзоры архитектуры), и **сохраняет грабли, обоснования и договорённости,
отличающиеся от умолчаний инструмента**.

## Что здесь применимо к нам не целиком

Статья написана про универсального помощника-программиста. У неё нет понятия «контракт
безопасности с оператором». Сдвиг «правила → суждение» бьёт по **стилевым** правилам;
переносить его на процедуру подтверждения необратимых операций нельзя — это не подпорка
под слабую модель, а обещание человеку. Сам Anthropic, вычистив текст, оставил
принуждение в коде (хуки, разрешения, режимы) — см. [конспект 06](06-secondary-sources.md).
