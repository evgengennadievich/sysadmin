# 04 — Документация Claude Code: практики и память

**Источники (живые документы, читаны 2026-07-25):**
- https://code.claude.com/docs/en/best-practices
- https://code.claude.com/docs/en/memory

---

## Часть 1. Ограничение, из которого растёт всё остальное

> «Most best practices are based on one constraint: Claude's context window fills up fast,
> and performance degrades as it fills.»

Окно контекста — **главный ресурс**. По мере заполнения модель начинает «забывать» ранние
инструкции и чаще ошибаться. Отсюда всё: короткий CLAUDE.md, подгрузка по надобности,
субагенты для исследования, `/clear` между задачами.

## Часть 2. Каким должен быть CLAUDE.md

**Размер: ориентир до 200 строк.** Длиннее — больше контекста и **хуже следование**.

> Наше ядро — 417 строк / 42 КБ. Разбор этого расхождения — в [GAP-ANALYSIS.md](GAP-ANALYSIS.md).

**Тест каждой строки:** «Если убрать эту строку, начнёт ли Claude ошибаться?» Нет — вырезай.

> «Bloated CLAUDE.md files cause Claude to ignore your actual instructions!»

**Таблица включать / исключать:**

| ✅ Включать | ❌ Исключать |
|---|---|
| Команды, которые нельзя угадать | То, что видно из чтения кода |
| Правила стиля, отличные от умолчаний | Стандартные соглашения языка |
| Как запускать тесты, чем именно | Подробная документация API (лучше ссылка) |
| Договорённости репозитория (ветки, PR) | То, что часто меняется |
| Архитектурные решения этого проекта | Длинные объяснения и учебники |
| Причуды окружения (нужные переменные) | Пофайловое описание кодовой базы |
| Грабли и неочевидное поведение | Самоочевидное вроде «пиши чистый код» |

**Диагностика по симптому:**
- Модель упорно делает не то, хотя правило есть → **файл слишком длинный, правило потерялось**.
- Модель спрашивает то, что в CLAUDE.md написано → **формулировка двусмысленная**.

**Требование конкретности** — формулировка должна быть проверяемой:
- «Использовать отступ в 2 пробела» вместо «форматируй код правильно».
- «Запускать `npm test` перед коммитом» вместо «тестируй изменения».

**Противоречия недопустимы:** если два правила спорят, модель выберет одно произвольно.
Периодически вычищать устаревшее и конфликтующее.

**Важное про природу CLAUDE.md:**

> «CLAUDE.md content is delivered as a user message after the system prompt, not as part
> of the system prompt itself. Claude reads it and tries to follow it, but there's no
> guarantee of strict compliance.»

То есть CLAUDE.md — **контекст, а не конфигурация**. Гарантии он не даёт. Если действие
должно происходить обязательно — это хук, а не строчка в файле.

## Часть 3. Разделение: контекст, правила, хуки

Документация про память формулирует это прямо:

| Задача | Куда |
|---|---|
| Заблокировать инструмент, команду, путь | Настройки: `permissions.deny` |
| Изолировать в песочнице | Настройки: `sandbox.enabled` |
| Стиль и качество кода | CLAUDE.md |
| Поведенческие указания | CLAUDE.md |

> «Settings rules are enforced by the client regardless of what Claude decides to do.
> CLAUDE.md instructions shape Claude's behavior but are not a hard enforcement layer.»

**Это и есть подтверждение нашего правила «правило, нарушенное дважды, идёт в код».**

## Часть 4. Автопамять — как она устроена

Два механизма памяти, оба грузятся в начале каждой сессии:

|  | CLAUDE.md | Автопамять |
|---|---|---|
| Кто пишет | ты | сам Claude |
| Что внутри | инструкции и правила | усвоенное и замеченное |
| Область | проект / пользователь / организация | на репозиторий, общая для всех worktree |
| Грузится | каждую сессию целиком | каждую сессию, **первые 200 строк или 25 КБ** |

**Где лежит:** `~/.claude/projects/<проект>/memory/`, внутри `MEMORY.md` (индекс, грузится)
и тематические файлы (грузятся по требованию).

**Механика самоограничения:** после записи в `MEMORY.md` Claude Code меряет файл против
лимитов. Близко к лимиту — напоминает сократить: одна строка на запись, детали в
тематические файлы, устаревшее слить или выкинуть. Превысил — запись проходит, но
возвращается ошибка с требованием переписать индекс, потому что хвост за лимитом при
следующей загрузке просто отвалится.

> Это готовый рабочий образец «графа заметок с индексом» — ровно та архитектура, которую
> мы завели в приватном knowledge (ADR-0018): `00-index.md` + атомарные заметки.
> Anthropic пришёл к тому же независимо.

**Важное ограничение:** автопамять машинно-локальная, между машинами не синхронизируется,
в субагенты основной памяти не попадает.

## Часть 5. Что ещё сказано про рабочий процесс

- **Дай агенту способ проверить себя** — подробно в [конспекте 03](03-verification-loops.md).
- **Сначала исследуй, потом планируй, потом пиши.** Но: если правку можно описать одним
  предложением — планирование пропускать, оно тоже стоит контекста.
- **Исследование — субагентами.** Чтение десятков файлов не должно засорять основной диалог.
- **Состязательная проверка перед сдачей** — свежий субагент видит только изменение
  и критерии, не видит рассуждений, которые к нему привели.
  С оговоркой: проверяющий, которого попросили найти дыры, **найдёт их и в исправной работе** —
  надо явно ограничивать его корректностью и заявленными требованиями, иначе получишь
  переусложнение.
- **Пять типовых провалов:** мешанина задач в одной сессии; правка по кругу (после двух
  неудачных исправлений — сброс и новый, лучший запрос); перегруженный CLAUDE.md;
  разрыв «доверился, но не проверил»; бесконечное неограниченное исследование.
