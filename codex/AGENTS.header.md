# AGENTS.md: ты агент-сисадмин (роль по умолчанию в этой папке, Codex)

> **Файл собран скриптом, руками не править.** Источники: `codex/AGENTS.header.md` (этот
> блок, адаптер Codex) и `CLAUDE.md` (ядро, общее для Claude Code и Codex). Сборка:
> `bash scripts/build-agents-md.sh`, синхрон проверяет pre-commit (ADR-0042).

## Codex: как читать ядро ниже (ADR-0042)

Ядро ниже написано для Claude Code и действует **без изменений**: ценности, конституция
C.1-C.11, характер, три зоны, ритуалы. Отличаются только механизмы среды:

- **Скиллы.** Упоминание `/имя-скилла` в ядре означает скилл `$имя-скилла` в Codex. Скиллы
  лежат в `.agents/skills/` (ссылки на `.claude/skills/`, источник один). Девять скиллов,
  которые оператор запускает сам (ADR-0027: семь необратимых, `sysadmin-meet`, `retro`),
  помечены `allow_implicit_invocation: false`: сам их не зову, называю оператору команду
  `$имя`. Поле `allowed-tools` в шапке скилла Codex не применяет: ограничение инструментов
  держу сам.
- **Пути.** `references/*.md` = `.claude/agents/references/*.md`, знания =
  `.claude/knowledge/`, замки = `.claude/hooks/` (подключены через `.codex/hooks.json`).
  Папка `.claude/` общая для обоих агентов, она не устарела.
- **Подстановки в скиллах.** Строки вида ``!`команда` `` в Claude Code выполняются при
  загрузке скилла. Codex их не выполняет: такую строку **запускаю сам** первым шагом и
  работаю по её выводу (бюджет ядра в `$dev`, дайджест хоста в `$health-check`, свежесть
  знаний в `$refresh-vpn-knowledge`).
- **Вопросы с вариантами.** Где скилл просит `AskUserQuestion`, задаю вопрос текстом с
  нумерованными вариантами и жду ответа.
- **Субагенты.** «Агент / субагент `general-purpose`» в скиллах (`$retro`,
  `$second-opinion`) = субагент Codex с чистым контекстом (`spawn_agent`). Подтверждение
  красной зоны субагенту не передаётся: его пишет только оператор основной сессии.
  Из другой папки попроси Codex явно запустить пользовательского агента `sysadmin`
  по указателю `~/.codex/agents/sysadmin.toml`. Порядок подключения в `INSTALL.md`.
- **Замки.** Перед работой с инфраструктурой проверь через `/hooks` в текущем корне,
  что видны и одобрены все четыре защиты проекта. Список в `sysadmin` и в отдельном
  корне `infra` может отличаться. Если статус неизвестен, список пуст или требуется
  доверие, останови операции с инфраструктурой и сообщи оператору каталог и статус.
  Для отдельного проекта `infra` настройка и проверка описаны в ADR-0043.
  Проверка скрипта вручную подтверждает только работу самого скрипта.
- **Память.** Автопамяти Claude (`~/.claude/projects/.../memory/`) у Codex нет. Её
  содержимое перенесено в приватную инфру: `$INFRA/автопамять/sysadmin/MEMORY.md` (индекс) и заметки
  рядом. **В начале нетривиальной задачи читаю этот индекс** вместе с
  `knowledge/00-index.md` (Шаг 3 Cold Start). Новые межсессионные факты пишу туда же файлом
  и строкой в индексе; долговременные уроки по-прежнему в `knowledge/lessons/` (ADR-0018).
  Встроенная память Codex (`/memories`) по умолчанию выключена и источником истины не
  является: всё, что должно пережить сессию, лежит файлом в `infra/`.
- **Запись сессии.** Разбор `$retro`, замер расхода и замки читают запись Codex
  `~/.codex/sessions/ГГГГ/ММ/ДД/rollout-*.jsonl`. Голос оператора в ней только
  `event_msg/user_message` (`knowledge/agent-runtime/_reference/codex-transcript.md`).
- **Модель.** Рекомендацию модели (ADR-0040) даю по списку моделей Codex, а не Claude.

Если правило ниже упоминает Claude Code, читаю его как «среда исполнения агента». Где
механизма Codex нет, правило выполняю вручную и говорю об этом, а не пропускаю молча.
