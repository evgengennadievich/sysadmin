# Examples: agent in action

Эта директория содержит **обезличенные примеры реальных операционных задач**, проведённых агентом-сисадмином `@sysadmin`. Назначение — показать ученикам, **как агент работает на практике**, без раскрытия специфики конкретного сервера оператора.

## Что здесь есть

- `_template.md` — шаблон для разбора Diun-уведомления (новая версия Docker-образа). Используется как стартовая точка для каждого нового разбора.
- `diun-update-review-YYYY-MM-DD.md` — конкретные разборы, по одному файлу на инцидент (создаются по мере поступления Diun-уведомлений).

## Принципы обезличивания

Все примеры публикуются в публичный репозиторий проекта (см. решение «два репозитория» в этапе 8). Поэтому реальная специфика оператора заменяется плейсхолдерами:

- Реальные имена контейнеров → `<service-name>`
- Реальные домены → `<domain>` (или `<domain.tld>`)
- Реальные пути → `/opt/<service>/`
- IP-адреса → `<server-ip>`
- Telegram chat_id, токены, ключи, пароли → `<redacted>`
- Внутренние URL → `<internal-url>`

**Принципы операции (зоны доверия, 4-шаговая процедура, type-to-confirm) — те же, что в реальной работе.** Меняется только конкретика, не методология.

## Как создаётся новый пример

1. Скопировать `_template.md` → `diun-update-review-YYYY-MM-DD.md`
2. Заполнить 7 шагов разбора (см. структуру шаблона + 08-RESEARCH.md Часть 9.3)
3. **Обезличить** перед коммитом (проверить `grep` по реальным именам/IP/токенам)
4. Закоммитить в репо
5. Закрыть итоговый файл подписью «Last verified: YYYY-MM-DD» если разбор был применён в продакшене
