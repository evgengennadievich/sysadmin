# Установка sysadmin для Codex

Подключай существующую рабочую копию `sysadmin`, если она уже есть. В ней хранятся
правила агента, скиллы и скрипты. Приватную папку `infra` храни отдельно. В ней
лежат `infra-config.json`, инвентарь серверов, заметки и журнал инцидентов.
Набор проектов и выбор активного проекта задаёт локальный `agent-config.json`
в корне `sysadmin`.

## Подготовить рабочие папки

1. Проверь наличие `codex`, `git`, `bash`, `jq` и `python3`. В Windows используй
   Git Bash для скриптов оболочки.
2. Уточни у оператора пути к `sysadmin` и `infra` и проверь, какие файлы уже есть.
   Если рабочей копии ещё нет, уточни источник и версию. Изучи источник при
   предложении скачать код. До первого запуска сверь полученные файлы с
   источником и проверь установщик, хуки и разрешения.
3. Покажи оператору, какие файлы будут созданы или заменены, и получи согласие.
   Если нужно заменить существующий указатель или настройки, сначала сохрани
   их копию. Инвентарь существующего проекта используй на месте.
4. Перед первой рабочей сессией настрой лимит инструкций и доверие к папкам.

## Загрузить инструкции и включить защиты

Убедись, что в `~/.codex/config.toml` хватает места для общего и проектного
файлов инструкций. Ключ `project_doc_max_bytes` ставится до первой таблицы.
При подключении `infra` отдельной папкой добавь её точный абсолютный путь.
Меняй существующие записи точечно.

```toml
project_doc_max_bytes = 98304

[projects."<SYSADMIN_PATH>"]
trust_level = "trusted"

[projects."<INFRA_PATH>"]
trust_level = "trusted"
```

Доверие к проекту позволяет Codex прочитать его настройки. Каждую команду
защиты оператор отдельно просматривает и одобряет через `/hooks`.

Открой `sysadmin` в новом сеансе и вызови `$sysadmin-init`, чтобы настроить
проекты и выбрать активную `infra`. Скилл валидирует оба конфига. Если проверка
не прошла, исправь причину, которую показал скилл.

- В `sysadmin` открой `/hooks` и проверь четыре записи из `.codex/hooks.json`.
- Для отдельного Git-проекта `infra` выполни из корня `sysadmin`
  `python3 scripts/install-codex-infra-hooks.py "$INFRA_PATH"`. Затем открой
  Codex из `infra` и проверь четыре записи через `/hooks` там.
- После одобрения открой новый сеанс и проверь состояние защит. Безопасная
  проба описана в [ADR-0043](decisions/0043-single-use-red-zone-approval.md#подключение-в-отдельной-папке-infra).

## Запуск из другой папки

В `sysadmin` основная сессия читает `AGENTS.md` при открытии папки.
Для вызова из `infra` или другой папки попроси Codex явно запустить
пользовательского агента `sysadmin` и передай ему задачу.
Указатель `~/.codex/agents/sysadmin.toml` связывает роль с ядром в `sysadmin`.
В Codex его создаёт `$sysadmin-init`. Если нужно восстановить только указатель,
запусти в проверенной рабочей копии после согласования записи:

```bash
source .claude/skills/_lib/write-bridge.sh
write_codex_bridge "$SYSADMIN_PATH"
```

Начни с чтения ядра или поиска активного проекта. Проверь, что агент называет
реальный путь к `AGENTS.md`. Если используешь перенесённую оперативную память,
индекс находится в `$INFRA_PATH/автопамять/sysadmin/MEMORY.md`, заметки лежат рядом.

## Контрольная проверка

Запускай из корня `sysadmin`.

```bash
bash scripts/build-agents-md.sh --check
bash .claude/hooks/tests/test-codex-hooks.sh
bash scripts/run-evals.sh health-check --estimate --sample 1
bash scripts/run-evals.sh health-check --sample 1
```

Оценка считает число запросов без обращения к модели. Последний вызов
проверяет выбор скилла по трём контрольным фразам. Отчёт появится в
`.eval-results/`. Ошибка запуска или формы ответа обозначается как `ERROR`,
по такой строке нельзя судить о выборе скилла. Проверка исполнения защит
и вызов агента из другой папки выполняются отдельными пробами.

После настройки можно запустить `$sysadmin-meet`. Справочник проекта в
[README.md](README.md), изменения версий описаны в [UPGRADE.md](UPGRADE.md).
